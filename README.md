# SEQUENCE · 序列日志

一个本地优先的个人成长 RPG，用《诡秘之主》的“途径、序列、魔药、扮演法、晋升仪式”隐喻现实任务。它不是官方产品或完整复刻游戏，而是一个个人同人工具。

## 当前可用功能

- 多轮自由输入文字冒险：可输入行动、对白、观察或内心想法，不再受固定选项限制。
- 长章节流式生成，默认目标 1200–2500 中文字符；AI 不可用时使用本地长叙事回退。
- 世界状态裁判会更新地点、时间、线索、人物关系、物品、剧情旗标和死亡/受伤状态。
- 每回合自动存档，可撤回并建立新的平行时间线；关键节点可命名保存。
- 现实任务完成后自动生成“现实回响”剧情回合，但不会因此改变任务 XP 或隐藏奖励。
- 首页视觉小说式文字冒险：事件场景、打字机对白、分支选项、剧情旗标与状态 HUD。
- 本地规划 1 个主委托和 2 个支线；AI 可用时增强叙事，不可用时自动回退到本地模板。
- 扩展生活画像与字段级隐私授权：本地专用、区间摘要、完整发送。
- 事件历史、剧情选择、人物与场景资产使用 IndexedDB v2 持久化。

## AI 叙事配置

所有密钥只放在服务端 `.env.local`，不会写入浏览器数据库：

```bash
cp .env.example .env.local
```

```env
AI_PROTOCOL=responses
AI_PROVIDER=openai
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=your-key
AI_MODEL=gpt-5-mini
AI_NARRATIVE_MODEL=gpt-5-mini
AI_ADJUDICATOR_MODEL=gpt-5-mini
AI_IMAGE_MODEL=
```

- `AI_PROTOCOL=responses` 使用 OpenAI Responses API。
- `AI_PROTOCOL=chat-completions` 可用于兼容 OpenAI 的第三方网关。
- 不配置 `AI_API_KEY` 时，网站自动使用本地叙事模板。
- 只有同时配置 `AI_IMAGE_MODEL` 才启用事件插画；失败时回退到程序化场景。
- 图像提示词只包含虚构事件氛围，不发送个人资料。

### 在设置页切换供应商与模型强度（推荐）

打开“设置 → AI 接口与模型强度”即可切换，无需改代码或重启：

| 供应商 | 可选模型 | 说明 |
| --- | --- | --- |
| DeepSeek | DeepSeek V3、R1、**V4 Flash（快速）**、**V4 Pro（旗舰）** | 中文长文叙事性价比高 |
| 通义千问 Qwen | Qwen Turbo、Plus、**Qwen 3.8（深度思考）** | 可开启 `enable_thinking` |
| OpenAI | GPT-4.1 mini、GPT-5 mini、GPT-5 | Responses API |
| 自定义兼容网关 | 任意模型名 | OneAPI / vLLM / Ollama 等 |

- 叙事模型与裁定模型可分别选择，用快速模型跑日常、深度模型跑关键剧情。
- API Key 保存在服务端 `.sequence-ai.json`（已在 `.gitignore` 中），**不会进入浏览器数据库、导出备份或 AI 日志**；前端只拿到掩码提示，例如 `sk-cc…c259`。
- 供应商的 baseUrl 由服务端预设白名单决定，前端无法把请求指向任意地址（防 SSRF）；只有“自定义兼容网关”可填地址，且非本机必须为 https。
- 设置页提供“测试连接”，显示实际延迟与返回样本。
- `.env.local` 仍然有效：页面未保存配置时自动回退到环境变量；页面保存后优先使用页面配置。
- 未配置 Key 时自动使用本地叙事模板，功能不中断。

## 人物背景与长篇文字冒险

完整链路是三步：**转盘抽命运 → AI 生成人物背景 → 一键生成 1500–2500 字第一章 → 自由输入继续冒险**。

**① 命运转盘**（`/wheel`）：抽身份类型、事件变故、阵营教会、代号、地点，存为命运档案（等概率真随机、可复核随机字节、可重抽留痕、特殊池联动）。

**② 人物背景**：转盘页点「生成人物背景」，AI 依据命运档案写出姓名、年龄、职业、出身、外貌、性格、动机、秘密、随身物、弱点，以及一段 400–800 字的成文背景。生成后可手动修改再保存；保存会新建版本，旧背景自动归档为「前史」，已开始的章节不受影响。可在转盘页、冒险页、调查员档案页查看。

**③ 第一章**：回到「冒险」页点「开始第一章」。开篇走的是与其他回合相同的流式长文管线，直接产出 1500–2500 字的第一章，并照常生成建议行动与可拒绝的现实任务提案。第一章写入时间线，因此存档点、撤回、回看全部可用。

**连贯性保障**：每一轮的提示词都会强制注入人物档案全部字段、命运五类、世界状态（已知事实/开放线索/人物关系/持有物）、最近 6 回合与滚动摘要；并明确禁止重复上一段、禁止空泛排比、禁止破第四面墙（例如「你可以继续输入」）。目标篇幅可在「幕后控制台 → 公式与偏好 → 每章篇幅」切换（长篇 / 标准 / 简洁）。

**失败处理**：正文生成自动重试 1 次；仍失败则保留上一章不动，界面明确报错并给「重试」，不会用模板套话凑字数。未配置 API Key 时会直接提示去设置页配置。

**边界不变**：人物档案与命运只影响叙事与可拒绝的现实任务提案，不会改动 XP、等级、序列或消化度。
## 转盘的层级化抽取与作者补充设定

**三级地理**：抽取顺序为 身份类型 → **年代** → **大地点** → **小地点** → 阵营 → 遭遇 → 异常事件 → 随身物 → **代号**。

- 年代：第一纪～第五纪，**第五纪权重 4（约占 50%）**，其余四纪各 1；第四纪及以前会标注「历史/文献线」。
- 大地点**按纪元过滤**：第四纪只出所罗门/图铎/特伦索斯特帝国，第五纪只出鲁恩王国/因蒂斯共和国/弗萨克帝国等。
- 小地点**受大地点约束**（不会出现「因蒂斯共和国的贝克兰德」）；没有已核验城市的大区域回落到该区域本身作为标志性地点。
- 所有地名都经全文核验并附章节与行号，**禁止现实地名**（巴黎/伦敦等有测试拦截）。
- 代号**按阵营生成**：塔罗会出塔罗代号，风暴教会出代罚者/惩戒骑士，机械之心出机械之心成员等；未能核验职阶的阵营回落到阵营名。

**背景年份约束**：第五纪的年份限定在 1340–1370（原著主线约 1349–1350）；第一纪至第四纪只写「第X纪」，不编造年份，也不得替换成现实地名。

**作者补充设定入库**：`scripts/extract_author_content.py` 解析作者（爱潜水的乌贼）发布的 md，得到 **20 条途径 / 194 条能力 / 49 条配方**（愚者、原初魔女两条途径作者未发布，保持待补充）。能力在档案页优先展示并标「作者补充设定」，小说原文摘录折叠为补充；配方在「亵渎石板 → 魔药配方」按途径浏览。

```bash
python scripts/extract_author_content.py --source "<作者补充设定>.md" --pathways src/lib/lore/pathways.ts --output src/lib/lore/author-content.generated.json
python scripts/extract_world_hierarchy.py --source "<全文>.md" --output src/lib/lore/world.generated.json
```
## 档案：属性 · 技能 · 背包 · 人物关系

侧栏入口「档案」（原「调查员档案」）包含四个系统。

**核心属性改名（只改显示名）**：内部 key 与已有 XP 完全不动，任务与本地任务模板不受影响。

| key | 显示名 | 含义 |
| --- | --- | --- |
| intellect | 学识 | 学习、推理与知识整合 |
| body | 体质 | 运动、体力与健康习惯 |
| focus | 灵性 | 深度专注与注意力 |
| social | 魅力 | 沟通、关系与协作 |
| creativity | 灵感 | 写作、设计与新想法 |
| execution | 行动 | 启动、完成与持续推进 |
| will | 定力 | 面对阻力与长期坚持 |
| life | 事务 | 财务、整理与日常责任 |

状态条 SAN / 体力 / 专注 / 动力是另一套数据，不参与改名。

**技能**：技能名一律使用**已核验的序列名**（占卜家、小丑、魔术师…），覆盖全部 220 个序列；能力详情挂原著原文摘录，没有原文的标注「原作未披露·待补充」。当前 108 个序列有原文，112 个待补充——你补充内容时只需替换 `src/lib/lore/abilities.generated.json` 一处。

- 熟练度 0–1000，等级 **入门 0–99 / 熟练 100–299 / 精通 300–599 / 大师 600+**。
- 成长公式（公开可查）：任务「扮演契合度 ≥ 1」且完成时，当前序列技能 `+ round(难度 × 2 × 质量倍率)`；契合度 0.5 与无关任务不涨。撤销任务完成会同步回退。
- 衰减：14 天宽限，之后每 3 天 −1；**下限 = max(0, 峰值 × 60%, 当前等级门槛)**，等级永不回退，衰减写入 `skillEvents` 审计，只在打开档案页时惰性结算且幂等。
- 自建技能可手动命名并用「手动练习 +5」增长；途径序列技能不能手改。

重新生成技能数据（全文不进仓库）：

```bash
python scripts/extract_abilities.py \
  --source "<本地《诡秘之主》全文.md>" \
  --evidence src/lib/lore/evidence.generated.json \
  --pathways src/lib/lore/pathways.ts \
  --output src/lib/lore/abilities.generated.json
```

**背包**：一个界面同时展示「非凡物品 / 封印物 / 剧情持有物」。称手（主手物）同时只能一件；自建物品可新增与删除；剧情物品由故事产出，可标记丢失/消耗。底层两张表仍分离，剧情物品仍属于时间线。

**人物关系**：由剧情推进自动演变（AI 的 `upsert_actor` 会写入阵营、态度、标签与最近互动），界面**只读**。态度由关系值推导：≤ −40 敌对 / −39～−10 警惕 / −9～9 中立 / 10～39 友好 / ≥ 40 信任。

**影响剧情**：技能与关系都会进入 AI 上下文——提示词明确要求「只能使用已解锁技能范围内的能力」以及「关系为负或敌对/警惕的人不会轻易相助」。
## 命运转盘（诡秘转盘）

侧栏「命运转盘」是一个完全本地的抽取工具，参考 UP主「驯鼬染」《诡秘转盘》系列的开场转盘形态（顶部指针圆盘 + 类别选择器）。

- **抽的是命运，不是人物**：人物永远是现实中的你，途径由你自己选择；转盘只抽身份类型、事件变故、阵营与教会、代号、地点与时代。
- **身份闸门与特殊池**：`身份类型` 永远先抽。抽到「穿书者 / 旧日眷属 / 特殊眷属」会分别解锁穿书者池、非人池、特殊眷属池，其他类别的可用扇区随之增加（加法叠加）。
- **等概率真随机、可复核**：使用 `crypto.getRandomValues` + 拒绝采样，每次抽取都记录原始随机字节、池快照与池大小，历史里可查。重抽不惩罚、不隐藏，只如实计数。
- **命运档案**：抽完可存为命运档案，持续生效直到你重抽；旧档案自动归档保留。
- **首页开局**：「冒险」页显示命运芯片与「用转盘开局」，点击后才调用既有叙事接口生成章节（不自动消耗 API）。无 Key 时本地规划器也会按命运选择场景与模板。
- **来源标注**：内置选项都标来源 —— 转盘二创预设 / 原作塔罗代号 / 原作引用（地点与阵营由 `scripts/extract_entities.py` 在本地全文核验，附章节行号）/ 自制叙事装置。界面不会把自制内容伪装成原作设定。
- **现实任务边界**：只有「事件变故」与「地点与时代」两类属性可能附一个可拒绝的现实任务提案；命运档案不会改动 XP、等级、序列或消化度。
- 类别与扇区可自建、可停用；「恢复内置预设」只恢复内置内容，不会删除你自建的内容。

需要重新核验地点/阵营词条时（本地全文不进入仓库）：

```bash
python scripts/extract_wheel_entities.py \
  --source "<本地《诡秘之主》全文.txt>" \
  --output src/lib/lore/entities.generated.json
```
## 隐私边界

- 健康、预算和社交限制默认只发送区间摘要，可选择仅本机或完整发送。
- 发送前会生成本地上下文摘要；AI 请求日志保存在本机，API Key 不进入日志。
- 手机号、邮箱、精确地址、证件/银行卡和 URL 在发送前会被模式化移除。
- AI 只能改写叙事与选项，不能覆盖任务行动、完成标准、难度、XP、序列或失控规则。
- 完整小说文本不会进入仓库或发送给 AI；只使用核验生成的短证据片段。
- 从 22 条途径中单选一条主途径，从序列 9 开始向序列 0 晋升。
- 提供独立的“途径牌组”页面，可在选择角色后随时浏览全部 22 张大阿卡纳牌面。
- 使用 1909 年 Rider–Waite–Smith 公共领域塔罗牌图像，并叠加途径名与中文标题。
- 图像来源、原始作者和公版说明见 `public/tarot/LICENSES.md`。
- 任务创建、编辑、删除、完成、撤销；支持类型、优先级、难度、截止时间、预计用时、标签、属性和“扮演契合度”。
- 透明结算：基础消化值、质量倍率、状态倍率、扮演契合度会完整显示，可人工修正。
- 魔药消化账本、不可变结算记录、反向撤销事件与手动调整记录。
- 角色页显示途径、序列、能力、属性、成就、物品、现实晋升条件和失控记录。
- 四个状态值：SAN、体力、专注、动力。60 为中性，平均值为稳定度。
- 序列 4 或 3 时可转到相邻途径，保留总经验、属性和历史，重置当前消化度。
- 低稳定度不会自动结算；低于 15 后必须由用户主动确认“失控结算”。
- 习惯、7/30 天完成率、补记、跳过和休息日。
- 14 天经验、质量分布、属性经验和实际用时图表。
- 完整 JSON 备份/恢复、任务 CSV 导入/导出、主题和消化公式配置。
- IndexedDB/Dexie 本地持久化，无账号、无后端依赖。

## 备份与恢复

1. 打开“设置”。
2. “完整 JSON”导出会包含角色、序列、任务、结算、账本、习惯、现实条件和设置。
3. 导入 JSON 会先请求确认，然后替换当前数据库。
4. CSV 只导出和导入任务字段，适合在表格中批量整理。
5. “清除全部数据”需要输入 `清除全部` 才能执行。

浏览器站点数据、IndexedDB 和本地存储可能被浏览器清理。长期使用时应定期导出 JSON 备份。

## 部署

这是纯静态客户端数据应用，可以部署到 Vercel 或其他支持 Next.js 的平台：

```bash
pnpm build
```

IndexedDB 按“协议 + 域名”隔离。部署域名改变后，原域名的数据不会自动迁移，请先导出 JSON，再在新域名导入。

## 资料与规则边界

- 22 条途径和 220 个序列名称已建立静态索引。
- 序列资料包含来源链接与核验状态；当前首版优先保证名称、顺序、相邻关系和现实机制可运行，完整能力、魔药主辅材料和扮演守则会继续逐条核验。
- 资料库中标记为“待核验”的内容不会伪装成原作事实。
- 原作中的危险、黑暗或反社会仪式不会转化为现实伤害指令。现实晋升条件始终要求安全、合法、可编辑。
- 《诡秘之主》及相关名称、设定版权归原作者和权利方所有。本项目是非官方、非商业的个人工具。
- 首版不包含云同步、多人账户、PWA、序列之上晋升和完整装备经济。

## 主要规则

- 序列阶梯：`9 → 8 → 7 → 6 → 5 → 4 → 3 → 2 → 1 → 0`。
- 进入序列 5、4、3、2、1、0 前需要完成现实晋升仪式。
- 消化上限默认：`100 + 50 × (阶位-1) + 10 × (阶位-1)²`。
- 质量倍率：未达成 `0.5`、完成 `1.0`、良好 `1.5`、卓越 `2.0`。
- 扮演契合度：无关 `0`、间接 `0.5`、契合 `1.0`、高度契合 `1.5`。
- 状态平均值映射为 `0.5–1.5`，60 为中性。
- 最终消化值会保留保底、上限和完整事件记录。

python scripts/extract_lore.py \

## 共享部署保护（BYOK）

- 每位访客的 API Key 只保存在自己的浏览器里，请求时通过 `x-sequence-ai` 发给服务端转发，服务端不落盘、不写日志、不回落站长密钥。
- 如果公开分享站点，可设置服务端环境变量 `SHARE_ACCESS_CODE`。访客需要在「幕后控制台 → AI 接口与模型强度」里填写同一口令；口令只保存在访客浏览器并随 AI 请求发送。
- 可用 `AI_DAILY_LIMIT` 限制单个访客每天的 AI 请求次数；计数只存在服务端内存，不持久化、不收集身份信息。
- 便携包和部署包不得包含 `.env.local`、`.sequence-ai.json`、API Key 或访问口令。
- `public/lore/novel-index.json` 是本地全文检索索引，用于让生成内容有原著依据；如果分发对象不应获得该索引，请在打包前移除或替换为私有构建。

本地 AI 用量面板只记录最近请求的字符数、耗时和模型，token 数字是粗略估算，不代表供应商标单。
